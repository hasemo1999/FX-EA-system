# KPI検収基準 — 統一版（v2.6修正）

> 発注仕様書 v2.6 の KPI 記載を整理・統一し、検収時の解釈違いを防ぐための補足資料。

---

## 1. KPI（検収基準）

### 1.1 必須KPI（検収合否）

以下を **すべて** 満たした場合、Phase1 の検収合格とする。

| 指標 | 基準 | 備考 |
|------|------|------|
| **PF（Profit Factor）** | **≥ 1.20** | バックテスト結果レポート基準 |
| **最大ドローダウン（MaxDD）** | **≤ 10%** | 参考値目安（検収判定には PF を優先） |
| **WFE（Walk-Forward Efficiency）** | **≥ 0.70** | Walk-Forward 分析結果 |
| **Walk-Forward 合格率** | **≥ 70%** | 全ウィンドウ中の合格割合 |

### 1.2 参考KPI（開発目標）

開発の最適化目標として以下を参考値とする。**検収条件ではない。**

| 指標 | 目標 | 備考 |
|------|------|------|
| PF | 1.30 以上 | 最適化の上位目標 |
| MaxDD | 8% 以内 | より厳格なリスク管理目標 |
| トレード数 | 月 3〜10 回程度 | 過剰取引・過少取引の目安 |

### 1.3 数値の主語（どの結果を見るか）

- KPI 測定は **MT5 Strategy Tester のバックテスト結果レポート** を唯一の基準とする。
- PF / MaxDD は **手数料＋スリッページ込み** の値を使用する。
- 複数回テストした場合は、**双方合意のテスト条件（§2）で実行した1回の結果** を基準とする。

## 2. 検収テスト条件（固定）

同じ EA でも条件が異なれば結果が変わる。以下を固定する。

### 2.1 テスター設定

| 項目 | 固定値 |
|------|--------|
| プラットフォーム | MT5 Strategy Tester |
| モデル | **Every tick based on real ticks** |
| 通貨ペア | USDJPY |
| 時間足 | H1 |
| 初期証拠金 | 1,000,000 JPY |
| レバレッジ | 1:25（国内個人口座基準） |
| スプレッド | **固定値指定 or 変動（要合意）** — 合意なき場合は変動を使用 |
| 手数料 | ブローカー標準設定に従う |
| 遅延（Delay） | 0 ms（理想環境） |
| 最大同時ポジション数 | EA パラメータの MaxPositions に従う |

### 2.2 ブローカー / 口座条件

| 項目 | 指定 |
|------|------|
| ブローカー | OANDA MT5（または双方合意のブローカー） |
| 口座タイプ | デモ口座（検証用） |
| スワップ | テスター標準値を使用 |

### 2.3 ティックデータ

| 項目 | 指定 |
|------|------|
| データ出所 | MT5 内蔵データ（MetaQuotes 提供） |
| データ共有 | 発注者・受注者が **同一データソース** を使用する |
| 差異が出た場合 | 双方がデータの MD5 ハッシュを交換し、同一性を確認する |

### 2.4 テスト期間

| 区分 | 期間 |
|------|------|
| **バックテスト全体** | **2020/01/01 〜 2025/01/01** |
| **OOS（Out-of-Sample）** | **2023/01/01 〜 2024/12/31** |
| **IS（In-Sample）** | 2020/01/01 〜 2022/12/31 |

> **重要**: 同じ EA でも期間が異なると PF は 0.5 以上変動し得る。期間固定により検収がクリアになる。

## 3. 例外時の挙動（決め打ち）

### 3.1 注文失敗時

| シナリオ | 挙動 |
|----------|------|
| リクオート / 約定拒否 | 最大 **3回** リトライ（間隔: 1秒, 2秒, 4秒） |
| スリッページ過大（許容値超過） | 当該注文を見送り、次バーで再判定 |
| 回線断 / サーバー無応答 | 30秒待機後リトライ × 3回。失敗時は次バーまで見送り |
| リトライ全失敗 | ログ記録＋通知（Slack/LINE）、次バーで再判定 |

### 3.2 スプレッド急拡大時

| 項目 | 値 |
|------|-----|
| エントリー禁止スプレッド上限 | **5.0 pips** 超でエントリー禁止 |
| 禁止解除条件 | スプレッドが 5.0 pips 以下に戻った次バーの確定時 |

### 3.3 ポジション管理

| 項目 | 値 |
|------|-----|
| 最大同時ポジション数 | EA パラメータ `MaxPositions` に従う（デフォルト: 1） |
| 最大保有時間 | **72 時間**（超過時は成行決済） |

### 3.4 金曜停止の厳密化

| 項目 | 値 |
|------|-----|
| 時間基準 | **サーバー時間** |
| 新規エントリー停止 | 金曜 サーバー時間 22:00 以降はエントリー禁止 |
| 保有ポジション | 金曜 サーバー時間 22:00 に全ポジション成行決済 |
| 補足 | JST との変換はブローカーの UTC オフセットに依存。仕様書にはサーバー時間で記載し、JST 換算表を別途添付 |

## 4. 納品物の検収方法

### 4.1 納品物一覧（v2.6 準拠）

- mq5 / ex5 ファイル
- パラメータ設定ファイル（.set）
- 導入手順書
- ログ仕様書
- 正解チャート集

### 4.2 正解チャート集の検収基準

| 項目 | 基準 |
|------|------|
| 枚数 | 最低 **20 枚** |
| 期間 | OOS 期間（2023〜2024）から抽出 |
| パターン網羅 | Mode A: 最低 5 例、Mode B: 最低 5 例、見送り判定: 最低 5 例、決済判定: 最低 5 例 |
| 表示内容 | 矢印（エントリー/エグジット位置）、ZigZag ライン、EMA ライン |
| 「正解」判定ルール | エントリー矢印が **確定バーの始値 ± 1 pip 以内**、エグジット矢印が **決済バーの価格 ± 1 pip 以内** であること |

## 5. 契約面の補足（改修範囲の線引き）

### 5.1 無償改修の定義

> **無償改修** ＝ 同一仕様の範囲内で、必須 KPI（§1.1）達成のためのパラメータ調整・ロジック修正。

### 5.2 有償（別見積）の定義

> **仕様変更** ＝ Phase1 スコープ外の機能追加・変更。以下を含むがこれに限らない：
> - トレーリングストップの追加
> - ロット可変化（動的ロットサイズ変更ロジック）
> - 新規通貨ペア対応
> - 新規時間足対応
> - Phase1 に含まないと明記された機能すべて

### 5.3 判定フロー

```
KPI 未達 → 同一仕様の範囲？
  ├─ YES → 無償改修（受注者負担）
  └─ NO  → 仕様変更として別途見積
```
